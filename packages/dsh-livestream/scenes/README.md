# 代码场景（直播间的可控画面组件）

直播不是做视频：画面要在她讲的时候实时编排。所以组件**提前做好**，每个场景是一张 HTML 页面，暴露**参数**和**动作**，她边讲边用台词标记驱动：

```
开到一半之前[[set open=0.4]][[do pour]]水几乎下不去，过了一半[[set open=0.6]][[do pour]]一下冲到底。
```

## 放在哪

- 通用场景库：`scenes/<名字>.html`，舞台从 `/scenes/<名字>.html` 读。后台交的素材里写 `src: @<名字>.html` 引用。
- 场景只做通用的机制（概率、渗流、函数……），不写死具体话题的内容；话题相关的文字、数据都从参数进来。

后台交的素材块：

````
```visual scene perc
title: 渗流：缝开到多少水才渗到底
src: @percolation.html
params: open=0.3
controls: open 缝隙比例 0–1；do pour 倒水；do reset 重来；do reroll 换一块石头
```
````

`controls` 一行写清有哪些参数（名字、含义、范围）和动作，她只看这一行就知道怎么用。

## 场景页面要做到

1. 定义 `window.scene = { set(params), do(action) }`：
   - `set(params)`：参数对象（数字、文字、布尔），只含要改的键，没给的保持原值。会被重复调用，同样的值要幂等。
   - `do(action)`：动作名，执行一次（比如「倒水」「下一步」「重来」）。不认识的动作忽略。
   - 页面加载完时舞台会先 `set(当前全部参数)`，再按顺序把做过的动作重放一遍（中途打开页面的观众要看到同样的状态），所以动作要能快速重放：重放时可以直接跳到结果，不用每个都播完动画（`do(action, { replay: true })` 第二个参数会告诉你）。
2. 自己用 `requestAnimationFrame` 画，铺满 iframe（`100vw × 100vh`），**随容器大小自适应**：同一个场景会被放进 1400×900 的主画面、680×900 的半边、590×370 的小块。
3. 背景透明（`html, body { background: transparent }`），外面已经有深色卡片。
4. 配色用舞台的：底 `#071226`、面板 `#0e1d40`、正文 `#eef3ff`、次要 `#8d9cc6`、强调鲸蓝 `#4d6bfe`、完成/正向海沫绿 `#8fe3d8`、警示草莓粉 `#ff6f8e`、金 `#f4c86a`。字体 `'PingFang SC', 'Noto Sans SC', sans-serif`，大标题可用 `'Smiley Sans'`（舞台已加载）。
5. 字要大：在 1400×900 的主画面里，正文不小于 28px，标注不小于 22px（按容器比例缩放）。
6. 不联网：只用本地的库（`/graphics/gsap.min.js` 已有；需要 d3、three 等放到 `scenes/vendor/` 再用相对路径引用）。
7. 轻：同屏可能还有 Live2D 和别的组件，保持 60fps，粒子类控制数量。
8. 页面开头写一段注释：场景名、一句话演示什么、参数表（名字、类型、范围、默认、含义）、动作表（名字、含义），跟素材块里的 `controls` 对得上。
