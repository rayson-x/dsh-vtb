新计时直接记录浏览器播放回执，不受约1秒轮询采样影响：P50 **6.725秒**，P95 **12.879秒**，最大 **12.987秒**。30条中20条在整个TTS响应结束前就开口，证明实际消费了尚未完成的音频流。

例如第20条在首音频可用后等待的7.057秒中，6.991秒是前一段真实发声；没有把已开口的句子为了数字强行剪断。第7条主要慢在口播提交前的10.244秒。后续须分别处理生成和自然交接，不能统称为TTS慢。

**30条互动回应中途缺音0次；全节目其他口播出现2次缓冲，约1.261秒与3.096秒。** 初始加载时的waiting不算中途缺音。背景缓冲也完整保留，不能把局部0次描述成全场零卡顿。下一步需改善生产速率抖动与预缓冲策略。

## 控制与工程验证

回归覆盖：并行预合成不提前发声；有界语句背压；HTTP在上游尚未结束时即可读到音频；字时标只能扩展已验证前缀，未返回的字不提前点亮；原子替换未开口旧句，版本冲突或已提交时整次拒绝；软切保留在播流。

新增硬切回归先复现了“取消TTS被提前写成failed”的错误，再验证修复。真实浏览器硬切也在TTS尚未完成时执行：观察到在播流后约27ms收到actual audio-aborted回执，最终状态aborted；整次请求与轮询耗时346ms。这是单次功能证据，不是统计SLA。

公开CI在0ab24e2通过；插件394通过/17跳过，宿主21、组件包18，SDK Node8。独立代码复核未接受P0/P1问题，复核本身不替代上述实际运行。

私有SDK的[远端CI](https://github.com/rayson-x/dsh-vtb/actions/runs/41766787217)也已通过：只读密钥、固定提交、46项依赖和SDK/Film测试；#18已关闭。没有公开私有实现或声称商业许可已购买。
