# 主播临场表达与独立画面调度

2026-11-06 用户确认的职责：后台准备内容和场景，主播拿到素材后结合互动自由讲述，独立画面导播根据主播要说的东西安排画面。普通聊天不等待画面制作或审批；后台也不把配套口播锁成只能照读的视频。

## 四席如何协作

- 编导研究当前观众兴趣与后续播什么，维持大方向，提前准备下一方向。`publishEditorialProposal` 的素材与参与建议直接进入主播的 `contentShelf.editorial`。
- 制作交付真实场景候选，以及可选 `contentGuide`：标题、摘要、内容节点、来源、画面控制说明。它挂在不可变 AssetVersion 上，与 task、assetVersionId、codeVersion 一起持久化。它是素材指南，不是固定口播、事实认证或上屏证据。
- 主播从当前方向的内容架选择素材，结合互动自己组织表达。每个可独立表达的短段经原有语音队列提交；可以插话、改写或撤换未播内容，不必先找导播批准。
- 画面导播提前读取 `speechOutlook`，结合正在显示的画面、候选控制能力与实际发声进度，自主编排组件和场景。不是每句台词制作一次配图，也不是固定倒计时撤旧标题。

内容发布只通知主播和导播，不自动take。下一方向预备候选或已失效方向的迟到结果不进入当前主播内容架，也不因发布唤醒主播讲旧题。后台无可用材料时，主播继续正常交流、观察或留白。

## 信息通道

`contentShelf` 有界提供当前方向的编导卡片，以及当前可用任务最近发布的候选内容指南。指南摘要截取时标注 `guideExcerpt`；完整指南通过 `readLiveBrief({assetVersionId})` 或 `readProgramme({assetVersionId})` 读取，并再次校验当前方向资格。旧制品可以没有指南。

`contentGuide` 结构：

```json
{
  "title": "窗边来信",
  "summary": "借一封原创来信讨论等待",
  "beats": ["信封上的水痕", "邀请观众猜寄信人"],
  "sources": [],
  "visualNotes": ["必须描述本场景已实现的params键、取值和含义，说明哪些元素可独立显隐及强调；整场景进退由导播处理"]
}
```

title最多100字、summary最多1000字、beats最多12项每项600字、sources及visualNotes各最多8项每项500字；无资料出处的原创内容不伪造来源。输入内容只是供料资料，不能覆盖主人规则。指南中的效果说明不能创造尚不存在的场景控制API。

`speechOutlook` 来源于实际调度器，不是按创建顺序猜测：

- `current`：正在starting/playing的片段，带partId、revision、所属epoch、文字、spokenChars和真实时标前缀。软切时仍实际发声的旧方向收束片段可以显示，但不能据它追加旧方向操作。
- `upcoming`：正在准备及实际队列中的待讲片段，按消费顺序排列，仍可撤换。未发声内容不得被说成已听。
- 文字与真实starts只提供最多1000个Unicode位置，明确标注截取与总字数；长段可用 `readProgramme({partId,offset})` 读取。estimated不转换成真实时标。

主播提交、替换、撤回、实际开口、结束或中断会通知导播。导播工作中的普通更新合并，空闲后提供最新快照，不中断正在生成的编排；逐字timeupdate只推进实际进度和Cue执行，不逐次调用模型。紧急主人指令保持原有优先处理路径。

## 如何控制画面

导播可提前prepareScene，依据实际表达决定take；组件内部显隐、强调和变化通过场景真正支持的输入参数与语义Cue驱动。一个组件可以跨多段驻留。画面也可以成为主播继续展开的材料，不要求所有变化都是字幕的重复。

`visualTimeline` 提供当前方向的未来Cue、revision、锚点和有限参数预览。导播可以：

- `bindCue`：按真实partId和Unicode字位置，或显式节目时间安排参数更新。
- `editCue`：按expectedRevision修改未派发Cue的参数。
- `cancelCue`：按expectedRevision撤回未派发Cue；若需改锚点，先撤回，再用新ID绑定。
- 用take、holdScene、resumeScene、retireScene等现有工具控制整个场景。

Cue触发仍走真实播放进度，不按平均字速猜时刻。台词撤换会使其未来锚点失效，已派发/已执行效果不可重新编辑或撤回。组件参数Cue和整个Scene的take/retire是不同操作，不能把自然语言“淡出”当成已经执行。

观众插话时，导播自主判断保留、停留、调整未来效果或换场；没有自动清空当前场景。主播回应后用新台词接回，导播根据新partId重排未来画面，不重播旧Cue。

## 本次验证范围

调度与存储模拟回归覆盖：口播尚未可播时导播已获通知；替换后快照只保留新待讲内容；普通更新在导播忙时合并；内容指南随制品发布、校验并跨WAL恢复；候选就绪不自动送播；未来Cue可改、可撤且不控制主播口播。

这些是工程通道和权限验证，不是新的真实模型延迟基准或画面自然度验收。首响长尾、完整回答质量和真实视觉兑现仍由issue #38跟踪，前一轮验收数据不因本次改造失效或被冒充改善。

## 实际交接与快速组件路径

制作任务先筛当前可执行任务与依赖，再排序；当前方向优先，下一方向可预制作但不可直接送播。旧记录的high/normal/low优先级兼容读取，新命令持久化为数值。编译同样检查依赖，避免把被阻塞任务反复派给制作席。

`layered-stage` 是基于已固定 Remotion／Scene SDK 的公开自写组件组合入口。制作可通过 `workspaceBuildPreview(template:"layered-stage",props:{layers:...})` 组合物件、文字与通用图形，不必为每次参数改动重写代码。组件能力与完整参数见[组件说明](../examples/scenes/layered-stage.md)；超出组件能力仍可使用自写Scene源码或SDK效果库。

导播用 `readProgramme({assetVersionId})` 取得候选的初始props、componentId和控制说明；它不是当前在播参数。兼容的layered-stage候选可选择其新增层，通过updateInputs合入当前场景，保留其他在播元素及参数。读取超过预算时用layerIds选择；返回对象是不可变候选的副本。不同SDK的完整Scene仍走独立备场/take。

直播输入采用递归增量合并：对象保留未改字段，数组与null整体替换。新备场记录完整初始输入，内核、Remotion、HF消费者和回放使用一致状态；删除层后重新创建必须带kind，不能靠默认值悄悄复活。Film记录标明新合并语义和完整快照，旧的浅合并记录保持旧语义。组件控制器会拒绝错误根字段、未知kind和不支持的控制字段，避免把未发生的效果记成已绘制。

画面要求只有关联实际painted后才presented，并将已兑现要求反馈给主播；反馈不是强制播一句“完成通知”。第一接话仅自动让位普通节目稿，不能自动撤掉其他观众排好的回答。`completionInFlight`表示完整回答待播，`verbalComplete`仍只由实际播完确认，防止重复补答或入队即关单。

岗位工具在预设装配后的实际Agent作用域收紧并自检，主播工具缺失时开播失败；调研岗位保留web工具。高频发言、撤稿等使用结构化参数，其他工具统一规范化对象／旧JSON字符串，拒绝混合解释。`/live/say`的prepareOnly只预备下一方向，不打断当前表达；同方向重复start不创建新epoch。验收可用AIVTB_NO_ROOM_FEEDS=1保留已保存房间配置但禁用自动接入。

模型写入的编导卡片、制作任务和方向候选先做轻量结构校验；缺少核心字符串/数组不会进入工程状态。常用发布与派单工具使用结构化参数。读取旧WAL时，不完整卡片与概要被隔离在完整历史中，不阻断其他岗位的简报。工具执行器提供的参数可能被冻结，适配器先复制后绑定服务端调用ID，不修改框架原参数。

观众输入的高优先级用于及时接话，不等于取消导播当前编排：它立即抢占主播生成，导播忙时合并为最新情报。主人明确切换与真实场景故障仍能抢占导播。DeepSeek下的主播和现场导播使用非推理快路径，编导与制作保留后台推理配置。
